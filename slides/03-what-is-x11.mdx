# X11 is a protocol, not a library

Not something you link against. A **byte stream over a socket**. Your program
is the client; something else owns the screen, the pixels and the memory the
window lives in.

You send it requests — `CreateWindow`, `MapWindow`, `PolyFillRectangle`,
`RenderCompositeGlyphs`. It sends back events and replies.

^^^

**First: the wire carries drawing, not pixels.**

You do not hand the server a framebuffer, you hand it a *description* — a
rectangle here, this colour; this glyph, at this position.

> So anything that can write bytes to a socket can be a GUI toolkit.
> That includes Node, with no bindings at all.

^^^

**Second: there is a network in the middle.**

Even over a Unix socket on this machine, the *shape* of the thing is a
network — because it was designed in 1987 to put a window from a mainframe
onto a terminal across a campus.

That decision is why the protocol is asynchronous, why a reply is something
you learn to avoid asking for, and why a third of this talk is about round
trips.
