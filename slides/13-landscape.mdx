# The question I have been putting off

Why would anyone build this? People run JavaScript on the desktop every day.

^^^

And they do it in one of **two** ways:

| wrap a browser | wrap a toolkit |
| --- | --- |
| **Electron** — ship Chromium and Node together | **nodegui** — Qt, over bindings |
| **Tauri** — borrow the OS webview, Rust behind it | **nodegui-react** — React onto those widgets |
| Neutralino, Wails — the same trade, smaller | **node-gtk** — GTK, through GObject introspection |
| your UI is a **web page** | **gtkx** — React onto *those* widgets |

^^^

Both are good answers, and I want to be clear about that. Electron ships the
editor most of this room writes code in. nodegui hands you real Qt widgets
that a Qt developer would recognise.

^^^

But look at what they have in common. **Both are wrappers.**

One wraps a rendering engine that was built for documents. The other wraps a
toolkit that was built for C++.

^^^

In neither case is the toolkit itself made of the language you are writing.
There is always a boundary, and the interesting question is **what that
boundary costs you** — which is different for each.
