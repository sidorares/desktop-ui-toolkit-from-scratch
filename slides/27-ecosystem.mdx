  Drag a node if the room is warm — it is a real graph, not a picture.
  If someone asks "doesn't yoga do the layout?" — good question, and the
  answer is on the edge between them. yoga owns the flexbox algorithm;
  react-x11 owns the yoga *tree*: a node per element, the measure functions
  text nodes answer with, and the dirty propagation that decides which
  subtree gets recomputed. The edge says `measure` because that is the half
  react-x11 supplies. Same shape as `damage`, which is the tree of
  what-changed it keeps between commits so that paint has something to skip.
  Beat 1: the spine. Workbench on top, a socket at the bottom, and an arrow
  means "depends on". The two dashed headless edges are not dependencies:
  the visualizer sits ON the wire when DISPLAY points at it, and
  react-devtools is joined by a websocket and nothing else.
  Worth saying out loud, since it is not drawn: the visualizer's own UI is a
  react-x11 app. It is a client of the thing it is debugging.
  Beat 2: everything JavaScript steps back, and three nodes stay lit — and
  the differences between those three are the whole point. Yoga is amber:
  compiled, but shipped as inlined WASM, so no toolchain and no node-gyp.
  x11-dri is optional and only for GL. AppKit is the one that actually broke
  the rule, and it bought macOS.
  This is the setup for the Cocoa slide. 90 seconds.
