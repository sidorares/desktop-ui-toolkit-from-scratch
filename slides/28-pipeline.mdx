# What happens when state changes

```
  setState
     │
     ▼
  reconcile ─────── render phase: pure, and discardable
     │
     ▼
  commit ────────── host mutations: create, append, update
     │
     ▼
  layout ────────── yoga, client-side, no round trip
     │
     ▼
  paint ─────────── damaged regions only
     │
     ▼
  the wire ──────── drawing commands, not pixels
```

^^^

Two of those stages are the whole performance story, and both are about the
socket.

**Layout never leaves the process.** If you asked the server "how wide is this
string" for every text node every frame, that is a round trip per
measurement — and a round trip is the most expensive thing available to you.
So font metrics come across once and get cached, and everything after that is
arithmetic on this side of the wire.

**Paint sends the smallest rectangle that changed.** A cursor blink in a
terminal is one cell, not one screen.
